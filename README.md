# 忘却前夜 · 战斗模拟器

本地网页版战斗模拟器框架：搜索角色/卡牌/怪物、设定等级难度、生成/消除卡牌、增减 buff/debuff、实时显示血量/buff/伤害计算明细，并内置「词条叠加规则」标注（加算/乘算/待确认）与待确认清单。

## 快速开始

**日常使用：双击 `start.bat`** → 自动启动本地服务并打开浏览器（http://127.0.0.1:8768）。
仍然支持双击 `index.html` 直接运行（悬浮窗功能需经 http 访问，故推荐 start.bat）。

- `test.html`：冒烟测试页，自动跑引擎断言（结果在页面上 + F12 控制台）。

## 🪟 游戏伴随悬浮窗（方案 B+）

玩游戏（无边框窗口模式）时点顶栏「🪟 悬浮窗」，获得置顶小窗：
- 采集窗内 **📸截图**（模拟器整页 PNG）与 **📷游戏画面**（屏幕捕获：可选 游戏/其他窗口/标签页，直接截游戏内画面）
- 手牌**实际数值**（含力量/易伤等当前状态，向上取整）
- 狂气时机：≥100 高亮「⚡可爆发」，200 上限打满标「超限」；银钥满 1000 高亮「钥令可用」
- 钥令系统：点底部「银钥」条开面板——设置携带钥令 / 释放（每回合第1次携带钥令、第2次尘封旧忆3选1、限2次，各耗1000银钥）/ 银钥觉醒（置入灵知觉醒，消耗每张翻倍、可透支为负）；29 钥令效果按研究深度自动结算，未建模部分日志标黄
- 💬 **问助手**：实时 AI 对话，每轮自动附带当前局面快照（AI 看着你的手牌和状态回答怎么打）

**AI 对话配置**：复制 `config.example.json` 为 `config.json`，填入 OpenAI 兼容端点的 `apiKey`（默认智谱 `glm-4.7`，可换任意兼容模型/端点）。Key 只留本机。未配置时对话框自动降级为「复制问题+局面」模式——粘贴到 ZCode 会话提问即可。

要求：Chrome/Edge 116+；游戏需无边框窗口模式（独占全屏会盖住悬浮窗）。

## 界面与流程

1. **准备阶段**：左侧面板四个页签（唤醒体/卡牌/怪物/Buff）搜索并「+添加」；顶栏设难度/等级。我方列在战场左侧、敌方列在右侧，默认从上往下依次受击。
2. **造物栏（顶栏第二行）**：携带的造物芯片 + 「管理造物」；右侧实时显示队伍属性（界域精通/伤害强效/黑印掉落/死亡抵抗/禁忌学识，点击查看明细）。
3. **队伍共享生命**：我方所有角色 HP 相加为一根总血条（我方列顶部）；每个角色保留独立狂气条，显示为 `35/100`、`15/200` 点数形式（上限可切 200）。
4. **编队分享码**：点右侧队伍属性打开面板，「📥粘贴编队码」导入游戏内 @@…@@ 分享码（解析预览→确认放置 60 级，缺角色标红跳过），「📋复制编队码」导出当前编队。只导角色——@@码不含等级，命轮/密契的 token 无法映射本库不硬塞（格式规范：dansa/SKeyDB，MIT）。
5. **唤醒体养成配置**（角色卡「⚙配置」）：
   - 属性（体质/攻击/防御/暴击率/暴击伤害/界域精通/伤害强效/黑印掉落/死亡抵抗/狂气回充/银钥充能）由 **等级+命轮+密契 自动计算，不可手动调整**
   - 可调项：等级（±1/±10）、启灵①②③开关、灵塑适性、内在灵格·疯狂预兆
   - 命轮最多 2 个；密契最多 6 个（互不相同，从「密契仓库」选取，仓库在 `data/pacts.js` 的 `pactInventory` 维护）
6. **出牌**：点击手牌 → 需要目标的卡再点对应单位；`✕` 直接消除手牌；算力 5/回合，狂气爆发不耗算力。
7. **沙盒干预**（随时可用）：生成任意卡牌到手牌、挂/减 buff、调队伍血量、调狂气/触腕/护盾、敌方调血。
8. **回合结束**：弃手牌 → 触腕结算 → buff 衰减 → 护盾移除 → 怪物行动 → 下一回合。
9. **机制面板**（顶栏按钮）：词条/buff 叠加规则总表 + 待确认清单 + 全局机制实现状态。

## 目录结构

```
index.html          主页面
test.html           测试页（引擎断言，结果在页面+F12 控制台）
css/style.css       深色主题样式
js/engine/          引擎：state(状态) cards(卡牌) buffs(状态系统) damage(伤害管线) turn(回合) tentacle(触腕) wheels(命轮) yogen(钥令)
js/ui/              界面：search board hand log mechanics collector(采集窗) map(地图) gear(养成配置) pip(悬浮窗)
js/ai/              advisor(融灾顾问) executor(推荐→模拟预览→采纳闭环)
data/               通用游戏数据：characters/cards/enemies/buffs/terms/wiki/growth/pacts…（纯 JS，直接编辑即生效）
data/personal/      个人账号数据（练度/命轮库存）——不入库，见该目录 README
test/run.js         测试用例
docs/               机制研究笔记/数据指南/融灾指导/差异报告
server.js           本地静态服务 + AI 对话代理（Key 只留本机）
```

## 数据来源与说明

- **角色/卡牌/命轮**：游戏公开 wiki（gamekee、灰机 wiki huijiwiki）与社区数据（SKeyDB）转录整理，版权归原始贡献者与游戏官方所有；词条/机制描述为游戏内文本转录
- **数值口径**：以游戏内实测与多源互证为准（过程记录见 `docs/MECHANICS.md`、`docs/MULTIPLIER-TESTS.md`）
- **不包含任何游戏素材**：本项目无立绘/音频/游戏原始资源，界面为自绘深色主题

## 个人数据（可选）

`data/personal/` 存放「我有什么、练到什么程度」的账号数据（练度/命轮库存），**公开仓库不含**。
把 `characters.template.js` / `fatewheels.template.js` 复制为同名 `.js` 并按注释填入即可；不放置时模拟器正常可用（个人向功能为空）。详见该目录 README。

## 验证伤害公式的推荐流程

1. 添加「木桩」+ 待测角色开战（木桩不还手）。
2. 从 Buff 页签给木桩挂易伤、给角色挂力量等，单一变量逐个叠加。
3. 出牌后在战斗日志展开「计算明细」，逐步对比游戏内实测值。
4. 哪一区的倍率对不上，就说明该区叠加规则/顺序需要修正 → 更新 `data/terms.js` 与 `docs/MECHANICS.md`。

数据收集与回填见 `docs/DATA-GUIDE.md`，机制研究记录见 `docs/MECHANICS.md`。
